# 心晴3.0

## Windows 桌面版 1.0

提供 Windows 10/11 x64 安装包和便携包。课程、日程、持续任务与子任务、长文心情和照片沿用 Android 的 CloudBase 同步协议；已有手机同步环境无需重建。左侧导航、中间日程／课表、右侧详情，长篇心情可展开写作。AI 聊天和密钥在电脑上独立保存。

首次在「设置与同步」填写手机现有环境和账号，以后自动恢复登录并同步。全部依赖安装、编译、实际 Windows 窗口测试和安装后启动验证均在 [Windows Desktop 工作流](https://github.com/hucw-11/xingqing3.0/actions/workflows/desktop.yml) 完成，本地不准备开发环境。使用方式、保存位置及当前限制见 [桌面版说明](desktop/README.md)。

## 1.5 日程与持续任务

- 日程中已完成待办和达到结束时间的课程统一移至底部「已完成／已结束」，默认折叠、卡片变灰。过了开始时间但未勾选完成的待办继续保留；课程结束不代表确认出席。
- 编辑活动可开启「持续任务（跨多天推进）」，自动保持全天、未完成顺延和不重复。日程上方仅显示一行持续任务摘要，点击展开紧凑卡片，按 DDL 排序；点卡片查看子任务。
- 旧的未完成、非重复、带子任务或顺延的活动可通过摘要行的「整理」批量移入，保留任务 ID、原计划、DDL 与子任务完成情况。
- 子任务可以「加入今天」或「移出今天」；加入后在全天区域显示引用卡片，与大任务共用状态，不创建副本。未完成时跨天保留，完成后移至完成当天的折叠区；大任务全部完成后统一显示母任务。
- 顺延的未完成活动与持续任务不在历史日期重复展示完整卡片。历史页面只显示当天完成或重新打开任务的进展摘要，点击可看全文。进展从本版本的操作开始记录，升级前未知的完成日期不会被编造补写。
- 每个重复活动的子任务、今日选择和进展记录相互独立。新字段随现有 CloudBase 记录同步，不需要重新初始化云端表；参与同步的手机均应更新到 1.5，以保留新的任务字段。
- 维持现有签名和应用身份，可覆盖升级。全部编译、数据库验证和设备回归继续放在 GitHub。

## 1.4 手机云端同步

支持 CloudBase PostgreSQL 环境下的多手机双向同步，入口在「设置 → 云端同步」。同一环境与账号共享课程、学期节次、活动、DDL、子任务、重复活动的单次状态、标签、心情长文及照片。本地保存不依赖网络，使用持久化同步队列和服务器版本号；删除通过保留的标记传播，冲突版本需手动选择。

前台约每 30 秒检查更新，保存后安排上传，后台由 Android 网络任务与周期任务调度，受系统省电策略影响。AI 聊天、未保存草稿、API Key 以及提醒权限和设备开关留在各手机。同步不是端到端加密，环境管理员可管理云端记录。照片暂不自动永久删除。

实际使用前需初始化自己的 CloudBase 环境并创建同步账号，详见 [手机同步配置](cloudbase/README.md)。源码和模拟双手机测试不能代替真实环境接入验收。沿用已有应用身份与签名，可覆盖升级。

## 1.3 更新

App 显示名称改为心晴3.0，安装包版本为 1.3.0。沿用 1.1、1.2 的应用身份和签名，可覆盖升级并保留数据。

- 日程分为全天、上午（00:00–12:00）、下午（12:00–18:00）、晚上（18:00–24:00），按开始时间归组；创建按钮悬浮在内容区域，滚动后仍可操作。
- 长按标签可选择编辑或删除，删除前确认，解除课程、活动及单次重复活动里的关联，不删除记录本身。
- 活动可以设置独立的 DDL，展示截止日期和倒计时。重复活动默认按与计划日的间隔计算每次 DDL，也可以单独编辑某次。
- 每天 08:30、14:30、19:30 发一条全天任务和 DDL 汇总通知：只列未完成的母任务，同一任务去重，顺延任务也纳入。DDL 进入 7 天内、3 天内、当天时加强文字标记，逾期未完成任务标为逾期。
- 实际有效课程开始前 15 分钟提醒。连堂只按第一节提醒一次；多个星期各自安排。修改、删除、手机重启或时区变化后重新调度。
- 在日程或课表的设置中进入「提醒设置」，允许系统通知；Android 12 及以后还可允许「准时提醒」。未授权准时提醒时会退回系统非精确定时并明确提示可能延迟。强行停止 App 后需重新打开，部分厂商手机还需允许后台运行。
- AI 支持多个独立对话的新建、命名、切换和删除。旧聊天迁移为「之前的对话」。删除对话不删除已保存的活动或心情。
- 新对话默认纯聊天，不读取 App 数据。每个对话分别设置是否读取资料、日期范围、照片和历史消息范围（不携带、20、50 或100 条），还可排除指定历史消息。
- 普通回复使用自然文本；只有需要新增时使用工具调用生成待确认卡片，仍需编辑并确认保存。
- 空回复和暂时性服务错误最多自动重试两次，失败后在原消息上手动重试。重试沿用原发送的资料和历史快照，不重复插入消息；切换对话或停止会作废迟到的回复。诊断仅保存错误类别、时间和重试次数，不记录 Key 或私人正文。

全部编译和自动测试在 GitHub Actions 进行，本地不安装 Android 编译环境。API 联网需用户在 App 内填写自己的 Key；自动测试使用模拟服务。

## 1.2 新增功能

- 底部三个入口：课表、日程、AI。旧版 1.1 的签名保持不变，可以直接覆盖安装。
- 课程星期支持多选，多个星期共用课程名称、教室、节次和周次。旧的单星期课程自动兼容。
- 课表右上角设置 → 课表导入／导出，使用本 App 的 JSON 文件，包含学期、12 节课时间、课程和标签，不包含日记、照片、聊天或 API Key。导入先预览，再选择合并或替换，完全相同的安排跳过，冲突提示。写入前保存本机课表备份，可从同一菜单恢复。不同学期或节次设置不能直接合并已有非空课表。
- 活动编辑页可添加一层子任务，子任务可改名、删除、独立勾选。时间轴卡片可展开子任务并完成活动。
- 开启「未完成自动顺延到下一天」后，未完成的每次任务会在后续日期的全天区域保留，显示原计划日期和顺延天数。完成状态、子任务和备注保留，各次重复任务不合并。课程不自动顺延。
- AI 设置中填写自己的 DeepSeek API Key。Key 经 Android Keystore 加密存储，不进入系统数据备份。请求仅发送到 DeepSeek 官方 HTTPS 接口，不经开发者服务器。
- 1.2 的 AI 默认读取当前选中日期、携带最近 20 条消息；1.3 改为每个对话独立设置，新对话默认纯聊天。资料日期范围最多 31 天。默认只发文字，心情照片需逐张勾选并显示缩略图，每次最多 9 张。模型名为 `deepseek-flash`。
- AI 可聊天、根据资料协助回顾情绪，提出活动和心情建议。每项建议先生成卡片，「编辑并保存」后进入原生编辑页，最终点保存才写入 App。可忽略建议。已保存建议不会再次写入。没有有效 Key 或网络时会显示错误，不伪造 AI 回复。
- 聊天和建议保存在本机，支持清空。尚未保存的心情建议有独立草稿，不覆盖原来的心情草稿。

云端使用模拟响应验证 AI 的请求范围、确认后保存及防重复逻辑，不使用开发者或用户的真实 Key。真实 DeepSeek 联网调用需在安装后填写 Key 试用。

接口参考：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)、[Vision](https://api-docs.deepseek.com/guides/vision/)。

## 1.1 新增功能

- 日程页提供「全部／活动／心情」切换，心情按记录时间插入上午或下午时间轴。
- 心情支持可选标题、长篇正文、五档心情和活力、自定义心情标签，每篇最多 9 张照片。点击卡片打开全文编辑页。
- 编辑内容自动保存为独立草稿，返回后可继续。拍照或相册导入的图片缩放到适合手机回看的尺寸并复制进应用，原相册删除不影响记录；不会上传。
- 活动和课程支持多个标签，日程页可筛选和管理标签名称、颜色。课程默认带学习标签。
- 重复活动可按天、间隔天数、指定星期、间隔周数和指定日期安排，可设截止日（含当天）、执行次数或持续重复。
- 每次活动独立完成；点击重复活动后选择「仅本次」或「本次及以后」，再编辑或删除。历史完成记录保留。
- 活动编辑页和课程卡片提供「记录感受」，记录会保存关联活动的名称与日期。删除活动不会删除日记。
- 保持原 applicationId，数据结构兼容旧版。由于 1.0 的开发签名缓存未成功保存，首次更换 1.1 需卸载 1.0；用户已确认旧版无须保留数据。1.1 起改为明确指定并在构建前缓存签名文件。缓存仍不替代长期发布所需的私有签名备份。卸载或清除应用数据会删除记录、草稿和照片。

自动验证新增：重复规则边界、独立完成与后续删除、长文草稿恢复、照片复制后原图删除仍可读取。

原生 Android 学生课表与日程 App，适用于 Android 8.0 及以上。浅灰背景、蓝色日期条、时间线卡片，底部提供课表、日程和 AI 三个入口。

## 使用

1. 在课表右上角设置开学日期、学期周数和 12 节课的时间。开学日期所在的周一到周日为第 1 周。
2. 点击课表空格录入课程，支持连续节次、指定周次、单周和双周。重叠课程会提示冲突。
3. 日程页点击日期切换，箭头切换周，点击月份可以选任意日期。「今天」返回当天。
4. 点击 ＋ 添加全天或定时日程；点击卡片编辑、完成或删除。课程卡片会打开对应课程的编辑表单，修改会影响整门课的所有周次。
5. 课程按当天星期和学期周次自动生成当天安排，按起始时间归入上午（12:00 前）、下午（12:00–18:00）或晚上（18:00 起）。修改节次时间会同步影响课表及日程。

内容离线保存在应用内部存储，正常关闭和重新打开会保留。卸载 App 或清除应用数据会删除本机记录。目前不提供账号、跨设备同步和节假日调课；提醒功能见 1.3 更新说明。

## GitHub 云端编译

本地无需安装 Java、Gradle、Android Studio 或 Android SDK。

提交代码后，GitHub → Actions → **Android APK** 会执行单元测试、Android Lint 和 APK 编译。通过后，在该次运行的 Artifacts 下载 **student-schedule-apk**，解压得到 `app-debug.apk`，传到 Android 手机安装。也可以在 Actions 手动点击 Run workflow。

这是供个人试用的 Debug 签名包。正式持续发布前应配置固定的私有签名密钥；签名不同的包无法直接覆盖安装。

## 代码

- `MainActivity.java`：原生界面、编辑表单、离线保存。
- `ScheduleRules.java`：学期周次、上课日期及时间校验。
- `ScheduleRulesTest.java`：开学周边界、周次范围、课程匹配、时间边界测试。
- `.github/workflows/android.yml`：完全在 GitHub 上准备环境、校验和编译。

构建版本固定为 AGP 8.7.3、Gradle 8.9、Java 17、compile SDK 35，兼容关系参见 [Android 官方文档](https://developer.android.com/build/releases/agp-8-7-0-release-notes)。
