# 心晴3.0 手机同步配置

本次为 Android 1.4.0，面向多台手机共用一个个人账号。所有编译和测试均在 GitHub Actions 运行，不要求本地安装 Android、Node 或数据库环境。

## 需要准备的云端服务

1. 在腾讯云 CloudBase 控制台创建一个 **PostgreSQL 模式**环境，可以先选择免费体验版。已有文档型数据库环境与本方案接口不同，不能直接填写其环境 ID。
2. 在身份认证中开启用户名密码登录，创建一个用于心晴的用户账号。两台手机使用这个账号，不使用腾讯云管理账号密码。无需把 SecretId、SecretKey、数据库管理密码或服务端 API Key 填进 App。
3. 打开此环境的 PostgreSQL SQL 编辑器，执行本目录的 [sync.sql](sync.sql)。它创建同步表、事务函数、私有照片桶及按用户隔离的权限规则。**不要在真实环境执行 test-bootstrap.sql 或 test-sync.sql**，后两者仅供 GitHub 的临时数据库测试。
4. 记下环境 ID，安装两台手机后分别打开「设置 → 云端同步」，填写同一环境 ID、同步用户名和密码，点击「登录并合并同步」。

启用前会保存本机 JSON 备份到应用内部 `sync-backups` 目录。主机首次上传后，新手机应能看到相同的课程、任务和日记。照片随记录上传；接收端会在后台下载照片。

## 同步范围与行为

- 同步：课程、学期及节次设置、活动与 DDL、重复规则及单次覆盖、母任务与子任务完成状态、心情正文与照片、活动标签。
- 本机保留：AI 对话、未保存草稿、DeepSeek Key、系统通知权限和每台设备的提醒开关。
- 本机保存不依赖联网；同步使用持久化 SQLite 队列、服务器版本号和幂等写入标识，不根据手机时钟判断谁覆盖谁。
- 前台打开主页面时拉取，页面停留期间每 30 秒检查；保存后约 2 秒安排同步。后台由 Android JobScheduler 安排网络任务及约 15 分钟周期任务，省电策略可能延迟，强行停止后需重新打开。
- 不同记录和可独立合并的字段自动合并；同一段文字同时修改、删除与修改相冲突时，进入「处理修改冲突」，显示两个版本，用户选择后才写回云端。选择前另做本机备份。
- 删除记录以持久化删除标记传播，避免离线旧手机复活记录。云端照片暂保留，不进行自动永久删除，防止仍在离线的设备和冲突版本失去附件；可由环境管理员在确认无引用后清理。
- 一台已绑定账号的手机支持退出并重新登录原账号。本版本拒绝直接绑定另一个账号，避免把已有私人记录合并进其他人的空间。
- 传输通过 HTTPS，云端权限按登录用户隔离；登录令牌使用 Android Keystore 加密后保存，排除系统备份。本版本不是端到端加密，环境管理员仍可管理数据库及照片。

## 验收顺序

1. 手机 A 添加活动、心情、照片，手机 B 同步后检查内容及照片。
2. 两端断网各自添加不同活动，联网后确认两边均保留。
3. 两端断网分别完成不同子任务及不同重复日期，联网后确认状态合并。
4. 两端同时修改同一篇心情正文，确认出现冲突入口且两个版本可读。
5. A 删除活动，B 后续联网不应重新创建它。
6. 退出、重新登录原账号、重启 App 后，确认未上传修改继续保留。

GitHub 另外验证 PostgreSQL 事务写入、旧版本拒写、重复请求幂等、跨账号行隔离和照片权限。设备测试用两个隔离的数据目录及模拟 CloudBase 服务验证同步引擎；真实环境接入后仍需按以上步骤完成实机验收。

接口依据：[用户名密码登录](https://docs.cloudbase.net/en/http-api/auth/auth-sign-in)、[令牌刷新](https://docs.cloudbase.net/http-api/auth/auth-grant-token)、[PostgreSQL RPC](https://docs.cloudbase.net/en/database/postgresql/http/rpc)、[PG 存储接口](https://docs.cloudbase.net/http-api/storage-pg/pg-storage-api)。
